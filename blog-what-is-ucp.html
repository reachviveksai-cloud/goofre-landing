UCP: how Goofre™ scores agentic-commerce readiness

6 min read · Protocols · Updated 2026

UCP is Goofre™'s own readiness model. It takes the vague, unanswerable question every merchant is now asking, "are we AI-ready?", and turns it into a graded, fixable score. UCP is not an outside standard you must comply with. It is how Goofre™ measures a store against the external standards and the structured-data foundations beneath them.

Let us be precise, because the naming in this space gets muddled fast. The open standards for agentic commerce are ACP, AP2 and MCP, plus the Schema.org structured data that everything else sits on. Those are external specifications, authored outside Goofre™, and we cover them in a sibling article. UCP is different. UCP is Goofre™'s readiness framework: the instrument that scores how well a given store actually satisfies those standards in practice. You do not implement UCP. Your store gets measured by it.

What UCP actually is

Ask a developer "is our store AI-ready?" and you get a shrug, because the question has no natural unit. Ready for what? Measured how? Passing or failing which bar? UCP exists to give that question a number and, more usefully, a punch list. It grades a store, tells you which parts are strong, which parts silently fail an agent, and which fix moves the needle most. The output is not a vibe. It is a score with a remediation path attached.

The factor set that produces the score is not a marketing artifact you have to hunt for. It ships inside every audit report, so an Agentic Commerce Orchestrator™ (ACO™) and the merchant see the same evidence: what was tested, what passed, what did not, and why it matters. We keep the exact factor list unquantified here on purpose, because the point is not a magic count of checks. The point is that the model tests the things that decide whether an agent can find, trust and buy from you.

Five layers, mapped to the real standards

UCP grades a store across five layers, and each one gates the next. This is the same stack an AI shopping agent walks in order, which is why UCP scores in that order rather than treating every check as equal.

  • Access. Can an agent reach your content at all? Crawler permissions, retrievable data, and endpoints an agent can actually call. This is where MCP, the model context protocol for exposing tools and data to agents, comes into the picture.
  • Comprehension. Can it understand what it reached? This is Schema.org structured data: Product, Offer, price, availability, and feeds that agree with the page.
  • Identity and trust. Can an agent trust you enough to act? Verified business identity and machine-readable policies, the ground that AP2, the agent payments protocol, needs before money moves.
  • Transactability. Can it actually buy? A checkout an agent can drive and quotable terms, the domain of ACP, the agentic commerce protocol.
  • Reliability. Does it stay true over time? Stock and price that match reality, so a store an agent recommended once is not wrong the next time it looks.

Mapping each layer to a specific external standard is deliberate. It means a UCP score is not an opinion about your store. It is a statement about how far your store carries a real agent, using ACP, AP2, MCP and structured data as the yardsticks.

Why the score is transactability-weighted

A free readiness checker asks a shallow question: is the tag present? UCP asks a harder one: could an agent actually act on it? Those are not the same test, and the gap between them is where most stores lose sales they never see. A Product markup can validate cleanly and still carry a price that disagrees with the feed. A return policy can exist and still live only in a PDF an agent cannot quote. A checkout can load and still trap a machine at a modal.

So UCP runs tougher on purpose. The score is weighted toward transactability, because being mentioned by an agent is marketing and being buyable by one is revenue. A store can light up green on comprehension and still score poorly under UCP if an agent cannot verify it or cannot complete a purchase. That is the intended behavior. UCP is built to predict the sale, not to reward the tag.

A free checker asks whether a tag is present. UCP asks whether an agent could actually buy.

Honest trajectory: every audit records its engine version

Readiness is not a one-time grade. Standards move, agents get stricter, and your catalogue drifts. That creates a subtle trap: if the scoring engine changes between two audits, a month-over-month comparison is meaningless, because you are comparing two different rulers. UCP avoids that trap by stamping every audit with the engine version that produced it.

That single piece of bookkeeping is what makes trajectory honest. When a merchant sees their score climb from one month to the next, an ACO™ can say with confidence whether the store genuinely improved or the ruler simply changed. Comparability is not a nice-to-have in a field this young. It is the difference between a real progress report and a flattering chart.

How an ACO™ turns the score into work

A number on its own does not fix anything. The value of UCP is that it hands an Agentic Commerce Orchestrator™ an ordered queue. Because the layers gate each other, the priority is not guesswork: an access failure outranks a comprehension gap, and a trust gap outranks a cosmetic one, since nothing above a broken layer can pay off until that layer is fixed.

So an ACO™ works the UCP report top down, closing the gaps that unlock the most agent behavior first, then re-auditing to confirm the score moved for real. That is the loop Goofre™ is built around: measure with UCP, remediate in priority order, re-measure against the same versioned engine, and repeat as the standards evolve. It is how a store gets, and stays, genuinely buyable by agents, starting with Magento stores.

Key takeaways

  • UCP is Goofre™'s own readiness model, not an external standard to comply with.
  • It grades a store across five layers and maps them to ACP, AP2, MCP and Schema.org.
  • The score is transactability-weighted, so it runs tougher than a free tag checker.
  • Every audit records its engine version, so month-over-month trajectory is comparable.
  • An ACO™ uses the score to close gaps in priority order, then re-audits.
